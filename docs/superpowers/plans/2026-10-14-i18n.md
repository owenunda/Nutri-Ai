# App en varios idiomas (español + inglés): plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que NutriLife funcione en español e inglés: interfaz, errores del backend, correos con código y respuestas del chat con IA.

**Architecture:** La app usa `gen-l10n` (archivos `.arb`) y un `LocaleState` que guarda la preferencia (sistema/es/en) y la manda al backend en `Accept-Language`. Un middleware del backend fija `req.lang`. Con eso se traducen los errores (por mensaje de origen o por código), se elige la plantilla del correo y se pasa `language` a n8n.

**Tech Stack:** Flutter 3.44 (`flutter_localizations`, `intl`, gen-l10n), Dio, SharedPreferences. Node 22 + Express 5, `node --test`. n8n.

**Spec:** `docs/superpowers/specs/2026-10-14-i18n-design.md`

## Global Constraints

- Idiomas: `es` (por defecto) y `en`. Cualquier otro idioma o la falta del header cuenta como `es`.
- Preferencia guardada en `SharedPreferences` con la clave `app_language`, valores `system` | `es` | `en`.
- Plantilla ARB: `nutrilife/lib/l10n/app_es.arb`. `app_en.arb` debe tener exactamente las mismas claves.
- Claves ARB en camelCase con prefijo de feature (`auth`, `setup`, `home`, `meals`, `nutrition`, `chat`, `progress`, `profile`, `premium`, `legal`, `common`).
- Catálogo de alimentos y recetas guardadas: no se traducen.
- Rama `i18n` (sale de `feat/google-auth`). No se sube a `main` hasta que google-auth esté en `main`. **No hacer push** salvo que el usuario lo pida.
- Commits sin línea `Co-Authored-By` de Claude.
- Comentarios y mensajes de commit en español, con el estilo del repo: `feat(i18n): ...`, `test(i18n): ...`.
- Backend: `cd backend && npm test`. App: `cd nutrilife && flutter test` y `flutter analyze`.

## Cambio respecto al spec (decidido al escribir el plan)

Hoy la app traduce al español algunos mensajes del backend que vienen en inglés
(`_translateMessage` en `auth_repository.dart` y `setup_repository.dart`). Si el backend
pasa a mandar inglés a quien pide inglés, ese mapa los volvería a pasar a español. Por eso:

- El backend tiene una tabla `SOURCE_MESSAGES` (mensaje original → `{ es, en }`) que cubre
  los mensajes en inglés que necesitan español y los de validación de los dos idiomas.
- En `es`, el usuario ve lo mismo que hoy (el texto en español sale ahora del backend).
- La app borra sus `_translateMessage` y muestra el mensaje tal como llega.
- Los mensajes de éxito no se traducen: la app no los muestra (solo mira `success`).

```js
// backend/src/middleware/language.middleware.js

// Idioma de la respuesta según Accept-Language. La app lo manda en cada
// petición; sin header (apps viejas, panel de admin con otro idioma) queda en
// español, que es como respondía el backend antes.
export const SUPPORTED_LANGS = ['es', 'en'];
export const DEFAULT_LANG = 'es';

// "fr, en-US;q=0.8" -> 'en'. Ordena por q y, a igual q, por orden de aparición.
export const resolveLang = (header) => {
  if (typeof header !== 'string' || !header.trim()) return DEFAULT_LANG;

  const ranked = header
    .split(',')
    .map((part, index) => {
      const [tag, ...params] = part.trim().split(';');
      const qParam = params.map((p) => p.trim()).find((p) => p.startsWith('q='));
      return {
        lang: tag.trim().toLowerCase().split('-')[0],
        q: qParam ? Number(qParam.slice(2)) : 1,
        index,
      };
    })
    .filter((entry) => entry.lang && !Number.isNaN(entry.q) && entry.q > 0)
    .sort((a, b) => b.q - a.q || a.index - b.index);

  return ranked.find((entry) => SUPPORTED_LANGS.includes(entry.lang))?.lang ?? DEFAULT_LANG;
};

export const languageMiddleware = (req, res, next) => {
  req.lang = resolveLang(req.headers['accept-language']);
  next();
};
```

En `backend/src/app.js`, agrega el import junto a los demás middlewares:

```js

```

y móntalo justo después de `app.use(express.json());`:


**Interfaces:**
- Consumes: `req.lang` (Task 1).
- Produces: `localizeError({ code, message, details, params }, lang) → { message, details }`, `new AppError(message, status, code, details, params)` y `SOURCE_MESSAGES` / `CODE_MESSAGES`.

Cómo se resuelve un mensaje, en este orden:
1. `SOURCE_MESSAGES[mensajeOriginal][lang]`: traducción exacta del texto original.
2. `CODE_MESSAGES[lang][code]`: texto por código; puede ser una función `(params) => string`.
3. El mensaje original.

Cada detalle `{ field, message }` pasa solo por el paso 1.

```js
// backend/src/i18n/localize.js
import { CODE_MESSAGES, SOURCE_MESSAGES } from './messages.js';

const bySource = (message, lang) =>
  typeof message === 'string' ? SOURCE_MESSAGES[message]?.[lang] : undefined;

const byCode = (code, lang, params) => {
  const entry = CODE_MESSAGES[lang]?.[code];
  return typeof entry === 'function' ? entry(params ?? {}) : entry;
};

const localizeDetail = (detail, lang) => {
  if (!detail || typeof detail.message !== 'string') return detail;
  const translated = bySource(detail.message, lang);
  return translated ? { ...detail, message: translated } : detail;
};

// Mensaje y detalles de un error en el idioma pedido. Si no hay traducción,
// queda el texto original: nunca falla por una traducción que falte.
export const localizeError = ({ code, message, details = [], params } = {}, lang = 'es') => ({
  message: bySource(message, lang) ?? byCode(code, lang, params) ?? message,
  details: Array.isArray(details) ? details.map((d) => localizeDetail(d, lang)) : details,
});
```

```js
// `language`, y cada agente que escribe texto para el usuario recibe una

  'Agente: Modificar Receta',
  'Agente: Responder Pregunta',
  'Agente: Chat General',

Escribe todo el texto que ve el usuario en {{ $('${EXTRACT}').first().json.language === 'en' ? 'inglés' : 'español' }}. Los nombres de alimentos del catálogo pueden quedar como vienen. Las claves del JSON no se traducen.

`;

const assignments = extract.parameters.assignments.assignments;
if (!assignments.some((a) => a.name === 'language')) {
  assignments.push({
    id: 'f1a0c7d2-0006-4a11-9f01-0a1b2c3d4e06',
    name: 'language',

  for (const value of node.parameters.responses.values) {
    if (typeof value.content !== 'string' || value.content.includes(MARK)) continue;
    // El agente general fija el español en sus reglas; esa línea ahora la da la sección.
    value.content = value.content.replace('- En español, tono cercano.', '- Tono cercano.');
    const anchor = value.content.indexOf('Responde ÚNICAMENTE en JSON');
    value.content =
      anchor === -1
        ? `${value.content}\n\n${LANGUAGE_SECTION.trimEnd()}`
        : value.content.slice(0, anchor) + LANGUAGE_SECTION + value.content.slice(anchor);
  }
}

writeFileSync(path, `${JSON.stringify(flow, null, 2)}\n`);
console.log('Listo: idioma agregado al flujo.');
```

### Procedimiento para migrar textos (se usa en las Tasks 9 a 17)

Cada task de migración aplica estas reglas a los archivos que lista:

1. **Encontrar los textos.** Corre `grep -nE "'[^']*[A-Za-zÁÉÍÓÚáéíóúñ¿¡][^']*'" <archivo>` y revisa también los strings con comillas dobles. Se migra todo texto que vea el usuario: `Text(...)`, `title:`, `subtitle:`, `label:`, `hintText:`, `labelText:`, `tooltip:`, `semanticLabel:`, mensajes de `SnackBar`, diálogos, mensajes de error de repositorios y valores por defecto que se muestran. No se migran claves de API, rutas, nombres de assets, claves de `SharedPreferences`, valores que se envían al backend (por ejemplo, el `goal` que guarda la base) ni logs (`debugPrint`).
2. **Crear la clave en `app_es.arb`** (texto actual, sin cambios) **y en `app_en.arb`** (traducción natural, no literal, con el mismo tono cercano y tuteo implícito). Prefijo de la feature más un nombre corto: `authLoginTitle`, `authLoginEmailHint`. Los textos que se repiten en varias features (Cancelar, Guardar, Reintentar, Continuar, Cerrar) van una sola vez como `common...`. Antes de crear una clave nueva, busca en `app_es.arb` si ya existe una `common` con ese texto.
3. **Variables y plurales con ICU.** Nada de concatenar.

   ```json
   "homeGreeting": "Hola, {name}",
   "@homeGreeting": { "placeholders": { "name": { "type": "String" } } },
   "mealsItemsCount": "{count, plural, =1{1 alimento} other{{count} alimentos}}",
   "@mealsItemsCount": { "placeholders": { "count": { "type": "int" } } }
   ```

4. **Usar la clave.** En widgets, `context.l10n.authLoginTitle` (con `import '.../core/l10n/l10n.dart';`). Si el texto estaba en un `const` (`const Text('...')`), quita el `const` de ese widget y deja los `const` de los hijos que sí pueden serlo. En código sin `BuildContext` (repositorios, modelos, `static const`), usa `currentL10n.clave`. Una lista `static const` de textos pasa a ser un getter o una función que recibe `AppLocalizations`.
5. **Unidades y abreviaturas** (`kcal`, `g`, `ml`) quedan igual en los dos idiomas, salvo que formen parte de una frase.
6. **Fechas:** usa `shortWeekday` / `shortMonth` de `core/l10n/date_labels.dart` (Task 7) en vez de las listas fijas en español.
7. **Tests de widgets de esa feature:** si un test arma su propio `MaterialApp`, cámbialo por `l10nApp(...)` de `test/helpers/l10n_app.dart` (Task 5). Los `find.text('...')` en español siguen valiendo, porque el helper fija `es`.
8. **Verificación de cada task:**
   - `cd nutrilife && flutter gen-l10n && flutter analyze` sin errores nuevos.
   - `flutter test` todo PASS (incluye la paridad de claves de la Task 5).
   - `grep -nE "'[^'$]*[áéíóúñ¿¡][^']*'" <archivos de la task>` no devuelve textos visibles. Lo que quede debe ser algo de la regla 1 que no se migra; anótalo en el mensaje del commit si no es obvio.

```dart
// nutrilife/lib/core/state/locale_state.dart
import 'dart:ui';

import 'package:flutter/foundation.dart';
import 'package:shared_preferences/shared_preferences.dart';

enum LanguagePreference { system, es, en }

/// Idioma de la app. Sigue el patrón de BotMoodState: un ChangeNotifier
/// compartido que MaterialApp escucha, sin meter provider en el proyecto.
/// La red lo lee para mandar Accept-Language al backend.
class LocaleState extends ChangeNotifier {
  LocaleState({Locale Function()? deviceLocale})
      : _deviceLocale =
            deviceLocale ?? (() => PlatformDispatcher.instance.locale);

  static final LocaleState instance = LocaleState();

  static const _prefsKey = 'app_language';
  static const supportedCodes = ['es', 'en'];

  final Locale Function() _deviceLocale;
  LanguagePreference _preference = LanguagePreference.system;

  LanguagePreference get preference => _preference;

  /// `null` deja que Flutter elija según el teléfono.
  Locale? get locale => switch (_preference) {
        LanguagePreference.system => null,
        LanguagePreference.es => const Locale('es'),
        LanguagePreference.en => const Locale('en'),
      };

  /// Idioma efectivo: el elegido o, con `system`, el del teléfono si está
  /// soportado. Si no, español.
  String get languageCode {
    final chosen = locale;
    if (chosen != null) return chosen.languageCode;
    final device = _deviceLocale().languageCode;
    return supportedCodes.contains(device) ? device : 'es';
  }

  Future<void> load() async {
    final prefs = await SharedPreferences.getInstance();
    final saved = prefs.getString(_prefsKey);
    _preference = LanguagePreference.values.firstWhere(
      (p) => p.name == saved,
      orElse: () => LanguagePreference.system,
    );
  }

  Future<void> setPreference(LanguagePreference preference) async {
    if (preference == _preference) return;
    _preference = preference;
    notifyListeners();
    final prefs = await SharedPreferences.getInstance();
    await prefs.setString(_prefsKey, preference.name);
  }
}
```

```dart
import 'package:intl/intl.dart';

String _clean(String value) => value.replaceAll('.', '');

/// "Lun", "Mar", "Mié" / "Mon", "Tue": abreviatura con mayúscula y sin punto,
/// como las que usaban las tarjetas de la semana.

}
```

```dart
Future<void> showLanguageSheet(BuildContext context, {LocaleState? state}) {
  final localeState = state ?? LocaleState.instance;
  return showModalBottomSheet<void>(
    context: context,
```
